# 检索与 Agent 优化记录

时间：2026-10-27 ~ 2026-10-28  
数据集：dev（2009–2022），最终 452 题有 ground truth；held-out 未参与调参。

这份文档记录**每一轮优化的假设、实验与结论**，包括负结果。最终口径以 README 为准，
这里保留过程，便于复盘「为什么最后是这个配置」。

## 优化线路总览

```
起点：Recall@10 0.495，怀疑检索链路有问题
  │
  ├─ 第一步：先修评测，不调检索
  │    1. GT 指向章节导语          → 可用题 365 → 452
  │    2. tag→知识点指向泛化节点     → 168 题 GT 变化，指标几乎不变
  │    结论：低分有一部分是 GT 噪声，但修完指标没涨 → 继续找瓶颈
  │
  ├─ 第二步：定位瓶颈在排序，不在召回深度
  │    3. 候选池诊断：并集@10 0.65 / @50 0.85，放大池不影响 @10
  │    4. RRF 在 @10 损失 12pp
  │
  ├─ 第三步：融合与排序
  │    5. 加权 zscore 全面优于 RRF（+2pp）
  │    6. 节去重：题级命中 0.597 → 0.663，chunk 召回 0.514 → 0.377
  │    7. 生产配置 = zscore + 节去重（指标冲突，按产品目标选）
  │
  ├─ 第四步：继续加召回路（全部负结果）
  │    8. 原生 BM25：并集 +2.7pp，融合 -1pp
  │    9. 图谱兄弟扩展：不去重 +2.4pp，与节去重重叠
  │   10. reranker：Oracle 候选集（85% 含 GT）也只 +1pp
  │
  ├─ 第五步：分离生成侧
  │   11. Oracle Document：可判题 75%（概念 80 / 图表 70 / 计算 62.5）
  │   12. 计算题扩到 30 题：可判题 87%，空回答 23% 才是主因
  │   13. 单轮 80% > Oracle 75%：模型参数化知识补足了部分检索失败
  │
  └─ 第六步：补能力
      14. 父子结构：检索子块 → 父节给 LLM（不影响检索指标）
      15. 前置依赖边 + 学习路径（148 条，天然无环）
```

最终生产配置：`zscore 融合 + 小节去重 + 去掉图谱 + 按题型启用 BM25 + 返回 10 条`；
dev 452 题：Recall@10 0.382、Accuracy@10 **0.668**、MRR 0.371、P50 约 35–49ms。

## 1. 先修评测，而不是先调检索

### 1.1 GT 指向章节导语

抽检发现「完全二叉树」的 GT 指向第 5 章「【复习提示】」——导语把整章术语列了一遍，
而正文小节标题叫「几种特殊的二叉树」。

修复：GT 候选小节排除 `复习提示 / 考纲内容 / 本章小结 / 导学 / 前言` 等导语。

| 项 | 修复前 | 修复后 |
|---|---|---|
| 有 GT 题数 | 443 | 556 |
| dev 可用 | 365 | 452 |
| GT 指向导语 | 7 | 0 |

### 1.2 tag → 知识点映射指向泛化节点

| tag | 旧映射 |
|---|---|
| 入栈出栈序列 | 栈、栈、栈 |
| 总线指标 | 性能、性能 |
| 交换方式 | 方式、方式 |
| 处理机调度算法 | 度、度、算法、调度算法 |

根因：19 个空标题节点参与匹配；候选按「标题最短」排序。

修复：过滤空标题与单字节点；按字面覆盖度排序；GT 端过滤泛化标题。

结果：168 题 GT 变化，dev 可用仍 452，指标几乎不变
（S1 R@10 0.5139 → 0.5161）。**结论：GT 污染影响个例判断，不影响均值。**

### 1.3 指标补充

新增 `Precision@k`（分母固定 k）与 `Accuracy@k`（题级命中）。
在「GT 是单个小节」的口径下，Accuracy@10 与 Recall@10 的题级版本不是一回事：
GT 小节有多个 chunk 时，Accuracy 会高于 Recall。

## 2. 融合与排序

### 2.1 瓶颈定位

| 阶段 | Recall@10 | Recall@50 |
|---|---|---|
| dense | 0.5487 | 0.8075 |
| BGE-M3 sparse | 0.5796 | 0.8296 |
| graph | 0.1814 | 0.2832 |
| 三路并集（理论上限） | 0.6681 | 0.8894 |
| RRF 融合 | 0.53 左右 | 0.80 左右 |

放大候选池不影响 @10（截断损失 0），瓶颈在融合排序，不在召回深度。

### 2.2 zscore vs RRF

| 融合 | Recall@10 | Accuracy@10 | MRR |
|---|---|---|---|
| RRF k=60 | 0.4876 | 0.5708 | 0.2855 |
| RRF k=10 | 0.4967 | 0.5841 | 0.3363 |
| 加权 zscore | **0.5084** | **0.5951** | 0.3442 |

旧报告里 RRF 更好，当前索引下 zscore 反超。原因是分数归一化对三路分数量纲更稳。

### 2.3 节去重：题级命中 vs chunk 级召回

| 配置 | Recall@10 | Accuracy@10 | MRR |
|---|---|---|---|
| 三路 RRF | 0.5139 | 0.5973 | 0.3310 |
| zscore + 节去重(1) | 0.3774 | **0.6615** | 0.3482 |
| 四路 RRF + 节去重(1) | 0.3752 | **0.6659** | 0.3606 |

去重每节只留 1 条，必然压低 chunk 级 Recall，但 top-10 覆盖更多小节，
题级命中上升。**这是指标定义决定的取舍，不存在同时最优。**

生产选择：问答关心「有没有拿到正确小节」→ `zscore + 节去重`。

## 3. 负结果清单

避免后人重复踩坑：

1. **原生 BM25 融合不提升**
   - 单路：R@10 0.522、R@50 0.759
   - 四路并集：0.6947 / 0.9027（比三路 +2.7pp / +1.3pp）
   - 但融合后 0.5038 < 三路 0.5139
   - 原因：与 BGE-M3 sparse 信号高度重叠
2. **bge-reranker-v2-m3 不适合本任务**
   - 整链路消融：-5~7pp
   - Oracle 候选集（85% 含 GT）：Hit +1pp、MRR +0.0013、nDCG 略降
   - 结论：不是候选不够，是重排偏好与本任务相关性定义不一致
3. **图谱兄弟扩展与节去重收益重叠**
   - 不去重基线：Hit@10 0.577 → 0.602（+2.4pp）
   - 生产 dedup 基线：0.6327 → 0.6327，MRR -0.029，延迟 +95ms
   - 生产关闭，保留 `use_graph_expand`
4. **术语重排、section 聚合**：都导致下降（聚合 R@10 掉到 0.318）

## 7. 数据结构专项分析（2026-10-28）

最初看到 Oracle 里数据结构只有 55.6%，怀疑是该科目检索差。拆开看并非如此。

**检索侧**（生产配置，dev 452 题）：

| 数据结构分层 | 题数 | Hit@10 | Recall@10 |
|---|---|---|---|
| 概念 | 67 | 0.597 | 0.307 |
| 计算 | 10 | 0.700 | 0.267 |
| 图表 | 43 | 0.558 | 0.310 |

数据结构检索在四科里属于中上，不是短板。

**Oracle 侧的 9 道数据结构题**：5 对、2 个空回答、2 道计算题错。
55.6% 是小样本 + 空回答造成的。

**再把 50 题按题型拆开**：

| 题型 | 可判 | 正确 | 准确率 | 空回答 |
|---|---|---|---|---|
| 概念 | 25 | 20 | **80.0%** | 3 |
| 图表 | 10 | 7 | 70.0% | 2 |
| 计算 | 8 | 5 | **62.5%** | 1 |

**结论：生成侧真正的短板是计算题（62.5%）和空回答（12%），不是数据结构。**
下一步应该做计算题专项，或换稳定 endpoint 消除空回答噪声。

## 8. 计算题专项（Oracle，30 题，2026-10-28）

上一轮 Oracle 50 题里计算题只有 62.5%，样本仅 8 题。扩大到 30 题：

| 指标 | 结果 |
|---|---|
| 抽样 | 30 题（dev 计算题，固定种子） |
| 全部准确率 | 66.7% |
| **可判题（排除空回答）** | 23 题，**正确 20 道 = 87.0%** |
| 空回答 | **7 / 30 = 23%** |

分科目（样本小，仅参考）：数据结构 75%、计算机网络 78.6%、
操作系统 66.7%、组成原理 44.4%。

**结论修正**：计算题本身并不弱（可判题 87%）。上一轮看到的 62.5% 主要是
空回答拉低的。真正要解决的是**空回答**：

- 7 个空回答全部是模型把 `max_tokens` 消耗在思考上（`empty=True`）
- 这是模型/endpoint 问题，不是 408 计算能力问题
- 优化方向：换非强制思考的模型、或把预算提到 4000+、或缩短 prompt

3 道有回答但错的题（子网划分、IEEE754、IP 转发）才是真实的推理错误。

## 9. 前置依赖边与学习路径（2026-10-28）

图谱只有层级边，没有「学 A 之前要先会 B」。补法：

1. 候选只取**同一父节点下的相邻兄弟**（按导图顺序），共 427 对。
   天然无环，不需要环检测。
2. LLM 判定「学 B 是否必须先学 A」，标准写死为「A 的概念/原理被 B 直接使用」。
3. 接受 148 条，写入 Neo4j：`(A)-[:PREREQUISITE]->(B)`。
4. Agent 新增 `get_learning_path` 工具，沿边反向走。

实测：

```
系统调用：CPU运行模式 → 内核模式与用户模式 → 中断和异常的处理 → 系统调用
中断和异常的处理：CPU运行模式 → 内核模式与用户模式 → 中断和异常的处理
```

局限：只覆盖相邻兄弟，跨章依赖（存储系统 → Cache）没有；判定质量尚未人工抽检。

## 11. 模型对照与空正文降级

同一批 20 道 held-out 题，逐题对比三个模型：

| 模型 | 准确率 | 空回答 | 可判题准确率 | 平均延迟 |
|---|---|---|---|---|
| `sensenova-6.8-flash-lite` | **80%** | 2 | **88.9%** | 15.8s |
| `deepseek-v4-flash` | 75% | 2 | 83.3% | **23.9s** |
| `glm-5.2` | 75% | **0** | 75.0% | 14.9s |
| `deepseek-flash` | 70% | 1 | 73.7% | 15.9s |

`deepseek-v4-flash` 能关闭思考，但 RPM 很低（多次 429 退避），
空回答没有比 sensenova 少，延迟反而最高，不采用。

结论：主模型准确率最高但空回答多，备用模型空回答为 0 但准确率略低。
二选一都有损失，因此实现**主模型优先、空正文时降级到 `LLM_BACKUP_MODEL`**：

- 主模型空正文 → 翻倍预算重试一次 → 仍空 → 切备用模型
- 降级只发生在失败路径，不影响正常调用
- 单测模拟主模型返回空，断言调用序列 `main → main → backup`

## 12. Agent 按题型的成本分解（2026-10-28）

同一批 25 题，按题型看 Agent 与单轮：

| 题型 | 路由 | 工具数 | Agent 准确率 | 单轮 | Agent P50 | 单轮 P50 | 延迟倍数 |
|---|---|---|---|---|---|---|---|
| 概念 | 直连检索 | 2.0 | 88% | 88% | 6.3s | 6.4s | **1.0×** |
| 计算 | 检索+计算器 | 1.6 | 75% | 100% | 33.2s | 14.8s | 2.2× |
| 图表 | 检索+图解析 | 2.0 | 25% | 62% | 59.6s | 16.5s | **3.6×** |
| 跨科目 | 概念路径 | 2.0 | 100% | 0% | 12.7s | 6.8s | 1.9× |

解读：

- 概念题 1.0× 延迟、持平：路由对简单题不施加额外开销，这是有意的设计。
- 计算题 2.2× 反而更低：计算器要多一次 LLM 产出算式，空正文让收益没有兑现。
- 图表题 3.6×、25%：图解析让 prompt 更长，思考更容易吃光预算，空回答率最高。
- 跨科目仅 1 题，无统计意义。

**结论：按题型分流是对的，但「什么时候不该用 Agent」比「工具更多」更重要。**
当前短板是图表题的空正文，不是工具数量。

## 13. 检索并发化（2026-10-28）

原实现四路召回是串行 for 循环，总耗时等于各路之和（124ms）。
两处优化：

1. 查询只编码一次（dense/sparse 原先各调一次 `encode_query`，13ms/次）
2. 四路用线程池并行，总耗时变成 max(单路)

结果：总耗时 **124ms → 81ms**；dev 452 题 S1 的 P50 从 141ms → **79ms**，
P95 104ms，指标完全不变（R@10 0.5161 / Acc 0.5973 / MRR 0.3309）。
图谱路 43ms 是当前上限，继续降需要优化 Neo4j 查询。

**跨线程 GPU 调用**：API 的线程池把请求分散到不同 worker，8 线程并发调用同一
BGE-M3 时单次编码从 32ms 劣化到 254–285ms（CUDA context 跨线程开销）。
把 GPU 推理收敛到专用单线程执行器后，单次稳定 32ms，并发请求排队。
API 稳态检索总耗时 **52ms**（此前 121–152ms）。

## 14. 按题型自适应检索（2026-10-28）

不再固定用同一组召回路，而是按题型选：

| 题型 | 最优组合 | Acc@10 | 对照（三路含图谱） |
|---|---|---|---|
| 概念 | dense+sparse+bm25 | **0.6355** | 0.6032 |
| 计算 | dense+sparse（不加 bm25） | **0.7656** | 0.7188 |
| 图表 | dense+sparse+bm25 | **0.7368** | 0.6974 |

两个反直觉结论：

- **图谱路对三类题都是负贡献**，还多 30ms。它的价值在考点分析工具，
  不在通用召回（与早期消融一致）。
- **BM25 不是单纯负结果**：全题均匀融合会稀释排名，但概念/图表题分层后
  有 +1.0pp / +3.9pp，计算题才是负的。

落地：`DEFAULT_QA_CONFIG` 改为 dense+sparse+bm25、去图谱、返回 10 条；
Agent 在 `retrieve` 节点按 route 关闭计算题的 BM25。

整体：**Acc@10 0.633 → 0.668，Recall@10 0.355 → 0.382，
P50 130ms → 约 35–49ms**。

## 15. LLM 精排：验证后放弃（2026-10-28）

两阶段检索的第二阶段：候选 40 条 → 模型选 top-10。

- 原实现：prompt 8746 字符，600 token 被思考吃光，5 题验证全部回退，
  P50 15.2s，指标与 base 完全相同。
- 修复：候选缩到 20 条、摘要 80 字、max_tokens 1600、换 glm-5.2，
  能稳定返回编号。
- 但正常路径仍需 3–5s，是 base（63ms）的 50–80 倍。

**结论：时间成本不可接受，不接入在线问答。** 相关代码已移除，只在过程记录里保留结论。

## 16. 对抗性 Plan：规则可验证的质疑（2026-10-29）

目标：给备考 Plan 加一层「生成中实时质疑」，但不做成多个 LLM 互相评价。
核心取舍是**把可验证的判定交给规则，把主观项交给模型，且模型不能自己决定何时结束**。

### 16.1 设计

- **6 类规则全部是纯函数**：编造真题号、周学时超支、漏高频考点、前置顺序颠倒、
  高权重无引用、薄弱科目占比不足。每条挑战带 `evidence` 与 `locator`，离线可复现。
- **三个角色靠权限区分**：Planner 唯一能生成/修改 Plan；Critic 无工具、不能改；
  Expert 只在「规则 high 与 LLM high 同时存在」时介入，只给 keep/downgrade/drop。
- **退出由状态机决定**：`converged / max_rounds / stalled / degraded / budget`
  五种 `stop_reason`，模型没有「继续讨论」的权限。
- **角色模型分开**：Planner 用主模型，Critic 用空回答率更低的备用模型，
  Expert 默认回主模型（也可用 `ADV_EXPERT_MODEL` 指定第三个）。

### 16.2 评测一：合成注入

- 黄金 Plan 10 条，规则误报 **0**。
- 在黄金 Plan 上叠加 2 类不互相覆盖的错误，20 条、40 个 label，
  6 类错误逐类检出率 **100%**。
- 挑战精确率 80%：注入「假引用」会连带触发「高权重无有效引用」，属预期行为。
- 口径：合成注入不等于真实 Plan 质量，报告已标注。

### 16.3 评测二：单轮 vs 2 轮（同一轮次的反事实）

最初实现是两条独立臂各跑一次，实测很快暴露问题：同一科目单轮臂与 2 轮臂的
**初始 Plan 不同**，差异里混进了模型随机性（一次 Critic 给了 3 条挑战，
另一次 0 条）。改为**只跑一次 2 轮流程，把第 1 轮快照当作单轮臂**：
两臂共享同一个初始 Plan 与同一轮质疑，差异只来自「是否继续修订」，LLM 调用也少一半。

4 个薄弱科目各跑一次（模型：planner `sensenova-6.8-flash-lite`、
critic `glm-5.2`、expert 回主模型）：

| 指标 | 单轮 | 2 轮 | 差值 |
|---|---|---|---|
| 收敛率 | 75% | 100% | +25pp |
| 平均版本数 | 1.00 | 1.25 | +0.25 |
| 平均残留 high | 0.25 | 0.00 | −0.25 |
| 平均 LLM 调用 | 2.00 | 2.50 | +0.50 |
| 平均 token | 2270 | 3266 | +996 |
| P50 节点耗时 | 47.9s | 61.6s | +13.7s |
| P95 节点耗时 | 80.3s | 139.2s | +58.8s |

逐科目：

| 科目 | 单轮 | 2 轮 |
|---|---|---|
| 操作系统 | 第 1 轮收敛 / 0 残留 | 相同 |
| 数据结构 | 第 1 轮收敛 / 0 残留 | 相同 |
| 组成原理 | 第 1 轮收敛 / 0 残留 | 相同 |
| 计算机网络 | `max_rounds` / 1 残留 | 第 2 版收敛 / 0 残留 |

三个反直觉结论：

1. **4 个科目里 3 个首轮就收敛**，2 轮臂零额外调用。真实 LLM 生成的 Plan
   没有触发任何一条规则，与黄金集 0 误报一致：规则拦的是明确错误，
   合规 Plan 上不制造噪声，也就没有可修的东西。
2. **唯一需要修订的科目，high 来自 Critic 的主观挑战**（目标分 115 对 120 小时，
   可达性存疑），不是规则。修订 1 次后收敛，代价是 +86.2s、+2 次调用。
   因此这 1 例的收益不能记在规则头上，且主观判断未经人工核对。
3. **多轮不是默认更优**：首版有 high 时才值得付成本；首版干净时单轮与 2 轮
   结果相同。状态机的提前收敛（`converged` 优先于轮次判定）是必要的，
   否则会为了「跑满 2 轮」而多花一倍时间。

n=4，P50/P95 只作描述性统计；合成注入集的 100% 检出率不代表真实 Plan 质量。

### 16.4 实现中发现的三个坑

1. **LLM 挑战没有 `status` 字段**：`advance` 只统计 `status == "open"` 的 high，
   导致 Critic 提出的 high 被完全忽略、`converged` 误报。补默认值 `open`。
2. **摘要截断被当成事实**：`plan_digest` 只展示前 8 周，Critic 据此判断
   「第 9–12 周没有安排」。摘要必须显式标注「另有 N 周未展示」。
3. **证据路径只校验前缀**：`goal.score` 这种不存在的路径也能通过 `startswith("goal")`。
   改为按 `goal.* / priority_kps[i].* / weekly_plan[i].tasks[j].*` 逐段解析真实字段。

## 17. Plan 重构：日期驱动 + 高性价比考点（2026-10-29）

用户反馈：现在能填的信息太少，Plan 只有「科目 + 小时 + 知识点名」，不够详细；
时间应该从现在算到考研，而不是让用户拍脑袋填周数；要能做 408 全科规划；
要能说出自己的备考问题；经验贴只写方法，不推荐资料。

### 17.1 输入与时间

- 表单改为：考试日期（默认下一场 2026-12-19）、每天 408 小时、每周学习天数、
  四科进度、全科/单科、薄弱科目 1–2 个、自由文本问题。
- `remaining_days / remaining_weeks / weekly_hours` 全部派生。
  默认 2026-10-29 → 2026-12-19：**51 天 ≈ 8 周，4h×6=24h/周，192h**。
- 阶段按剩余时间压缩：8 周 = 基础 1 周 → 强化 2 周 → 真题 3 周 → 冲刺 2 周；
  进度好时自动省略基础。
- 阶段方法参考公开经验贴（含用户提供的「25 考研 408 126 分经验贴」）：
  一轮按章理解 + 课后选择题、大题标记；二轮刷题 + 重难点 + 错题归因；
  三轮错题优先 → 真题、早年不计时/近 3–5 年计时；四轮模考 + 错题三刷 + 高频清单。
  **只取方法，不复制资料/网课/老师**；阶段周数按用户剩余时间压缩，不照搬 6 个月。
  经验贴的「20 天数据结构 / 15 天计组 / 15 天操作系统 / 10 天网络」只作比例参考，
  实际按 408 分值权重 + 薄弱科目加权分配。
- 另外两篇高分经验贴（11408 404 分、22408 399 分）的共性：
  第一轮只看不练会云里雾里，每学完一节立刻做对应选择题、错题不攒；
  起步晚一门一门过（DS → 组成 + OS → 网络），极短周期用「每周主攻 + 维持」；
  强化第二轮内容快过、重点看一轮卡住和错题、固定题型专项练、选择题二刷说清选项；
  真题从 09 年开始、近 10 年套卷计时、二刷独立写完整步骤、模拟 3–5 套；
  冲刺快翻高频和错题，时间不够宁可少模拟也要真题再刷，考前收窄。

### 17.2 高性价比考点

- 只用真题统计：频次、近 5 年、计算/图表占比、年份跨度、知识点标题数、前置深度。
- `roi = 0.7×yield + 0.3×(1-cost)`；每科按剩余时间选前 10/15/20 个。
- 频次前 5、频次 ≥8、用户点名的 tag 必选；短周期长尾不新学。
- 实测 8 周每科覆盖约 **36–45%** 的历史 tag 次数（数据结构 45 / 计组 41 /
  操作系统 40 / 网络 37），不再假装全覆盖。

### 17.3 用户问题 → 动作

- 关键词路由：基础差→保留基础；时间不够→考点数 -2；做题慢→限时；
  记不住→间隔回顾；真题低→提前真题；具体知识点→匹配 tag 并提前。
- 每条问题输出 `concern_actions`（诊断/动作/阶段/检查点），不依赖 LLM。
- 时间类问题不覆盖表单的 daily_hours，只影响密度；两者矛盾以表单数字为准。

### 17.4 生成方式：结构确定性 + LLM 只写文案

- `planner.py` 先算出完整结构（阶段/份额/考点/周任务/concern_actions/模板 guide）。
- LLM 只把 guide 改写成经验贴；失败（空回答、含资料名、含伪造真题号）退回模板。
- 因此 **LLM 文案失败不再触发 `degraded`**；结构 Plan 始终完整。
- Guide 单独用 45s / 1 次重试的客户端，避免 429 重试把 150s 预算耗光。

### 17.5 评测

- 黄金 10 条（全科/单科、8/12/16/30 周、不同进度与问题）**0 误报**。
- 20 条注入 / 40 label **100% 逐类检出**；挑战精确率 **83.3%**（48 条中 40 条命中）。
- 单轮 vs 2 轮（新 goal，反事实）：

2026-10-29 完成 1 组（8 周全科、操作系统薄弱、带「时间不够 / 真题正确率低」问题）：

| 指标 | 单轮 | 2 轮 |
|---|---|---|
| 收敛率 | 0% | 100% |
| 版本数 | 1 | 3 |
| 残留 high | 2 | 0 |
| LLM 调用 | 2 | 4 |
| token | 4657 | 6925 |
| P50 节点耗时 | 26.9s | 103.3s |

- 单轮臂 v1 有 2 条 high（Critic 主观挑战：真题验收过高、薄弱科时间被稀释），
  2 轮修订后 0 残留；代价是约 3.8 倍节点耗时。
- 经验贴文案两条臂都是 LLM 生成；修订复用首版文案，不再每轮调用。
- **4 组全量在 endpoint 上持续 429（rpm exhausted），中途停止，没有强行补数**；
  规则评测不依赖 LLM，仍然完整。N=4 的单轮/2 轮结论待配额恢复后重跑。

### 17.6 实现坑

1. **规则和 ROI 口径不一致**：旧规则用 `any(q.subject==subject)` 统计 top5，
   会把只在别的科目考过的 tag 算进来；改为按科目内题数排序。
2. **薄弱科目 30% 被取整踩线**：0.30×24=7.2 → 7.0 → 实际 29.2%，规则误报。
   薄弱科目小时向上取到 0.5h，并优先从非薄弱科目扣余数。
3. **权重跨 40 个考点归一化**：前几名只有 0.03，`uncited_priority` 永远不触发；
   改为**科目内归一化**，前几名回到 0.15 以上。
4. **数据集文件陈旧**：改了生成器但 `adversarial_plans.jsonl` 还是旧 schema，
   评测出现 5/10 误报。必须先重建数据集再评测（或用版本号强制失效）。
5. **摘要截断被 Critic 误判**：只展示前 4 周时必须保留「另有 N 周未展示」，
   且截断时优先保留这句话。
6. **LLM 文案提到资料名**：按用户要求直接退回模板，不把「王道/网课/老师」
   写进经验贴。
7. **「可后置」不能乱标**：早期把没进 `must_learn` 的子项都放进 `later`，
   会把高频子项（如快速排序）标成可后置。改为只允许「低频且无计算/图表收益」
   的子项进 `later`，高频子项放进 `must_learn`。

## 18. LLM-only 基线与空回答修复（2026-10-29）

### 18.1 空回答修复

旧版选择题 prompt 要求「最后一行写 答案：X」，思考型模型把预算花在推理上，
正文为空；评测里空回答被当成「答错」，是 Agent 落后的主因之一（25 题里 5/7）。
这次改三处：

1. prompt 改为**第一行先写 `答案：X`**，再解释；即使后面被截断也能解析。
2. `max_tokens` 从 1600/2200 提到 3000；空正文时缩短上下文再试一次。
3. `AgentResult` / 评测行增加 `empty` 字段，空回答单独统计，不从分母剔除。

### 18.2 LLM-only 基线

新增第三条路径：不给任何上下文，只靠模型参数化知识作答；三条路径使用同一批题、
同一 PROD 检索配置（LLM-only 不检索）。用 2000 次 bootstrap 给准确率和配对差值
95% CI。

dev 21 题配对（概念 15 / 计算 6）：

| 路径 | 准确率 | 95% CI | 空回答率 | P50 |
|---|---|---|---|---|
| 纯 LLM（无检索） | 90.5% | [76.2, 100] | 0% | 3.0s |
| 单轮 RAG | 85.7% | [66.7, 100] | 0% | 5.1s |
| Agent | 95.2% | [85.7, 100] | 0% | 5.6s |

- Agent − 单轮 +9.5pp，CI **[0, +23.8]**：不显著。
- 单轮 − LLM-only −4.8pp，CI **[−23.8, +9.5]**：**dev 上没有可证明的 RAG 准确率增益**。
- Agent 改对 2 题（2016-15、2011-22），改错 0。
- 完整 46 题只跑完 LLM-only（87.0%）；单轮/Agent 到 20 题后被 endpoint 429 截断，
  没有强行补数，报告用三路径共同的 21 题配对集。

### 18.3 结论

1. **空回答修复有效**：这批题三条路径空回答都是 0%，Agent 从旧 64% 回到 95.2%。
2. **Agent 不再输给单轮，但也没有显著优势**：CI 下界 0，不能宣称「Agent 更好」。
3. **dev 不能证明 RAG 的价值**：LLM-only 90.5% 说明公开真题很可能在预训练语料里。
   下一步应做 **held-out 2026 / 私有题** 的 LLM-only 对照，以及引用可溯源性评估，
   而不是继续在 dev 上刷准确率。
